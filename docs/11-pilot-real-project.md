# 11. Pilot One Real Project

## Goal

Uji operating system pada pekerjaan nyata yang cukup kompleks untuk memunculkan failure mode.

Smoke test tidak cukup karena smoke test biasanya terlalu bersih.

## Good pilot characteristics

- punya technical + creative/ops dimensions;
- ada real constraints;
- punya deliverable nyata;
- ada founder gates;
- butuh dua atau lebih role;
- hasilnya bisa diverifikasi.

## Pilot flow

1. Pilih outcome tunggal yang penting.
2. Tentukan primary owner.
3. Owner retrieve Project HQ/context.
4. Owner buat specialist work.
5. Specialist mengembalikan evidence, bukan sekadar opinion.
6. Owner melakukan synthesis.
7. Verifikasi apakah founder perlu dilibatkan.
8. Audit apakah project state benar-benar bergerak tanpa manual prompting.

## What to measure

- apakah owner tetap owner setelah delegasi;
- apakah specialist menggunakan domain yang benar;
- apakah result evidence-based;
- apakah project selesai tanpa founder menjadi messenger;
- apakah blocker terklasifikasi dengan benar;
- apakah synthesis terjadi otomatis/event-driven.

## PASS criteria

Bukan "semua task selesai", tetapi **outcome owner mampu menyatukan hasil dan menentukan next state**.
