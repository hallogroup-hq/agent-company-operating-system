# 15. Add Agents Only on Proven Bottlenecks

## Goal

Mencegah "agent sprawl" - tim kelihatan canggih tetapi coordination cost tumbuh lebih cepat daripada value.

## Default stance

Roster kecil adalah feature, bukan kekurangan.

## Remedy order before adding an agent

1. correct routing;
2. clarify ownership;
3. improve Project HQ/context;
4. improve SOP;
5. add/refine narrow skill;
6. fix tool/capability access;
7. improve automation/workflow;
8. separate execution board;
9. only then evaluate a new durable role.

## NOT evidence for a new agent

- one difficult task;
- one long run;
- one blocked task;
- founder input required;
- missing tool integration;
- temporary project volume;
- one specialist technique;
- unassigned card;
- historical routing drift;
- stale/deprecated task.

## Evidence for a true role bottleneck

A new role is justified only if work is:

- recurring;
- materially substantial;
- coherent as one responsibility;
- not cleanly inside existing roles;
- still a problem after routing/SOP/skill/tool fixes;
- causing repeated overload/context mismatch;
- worthy of durable authority + state + triggers;
- expected to return meaningful time/decision load to the founder.

## New-agent proposal contract

Before creating role baru, tulis:

- Problem
- Evidence
- Why existing roles are insufficient
- Proposed role
- Boundaries
- Authority
- State
- Trigger
- Handoffs
- Expected ROI
- Risks

## PASS criteria

"Tidak menambah agent" adalah outcome valid bahkan ideal bila bottleneck belum terbukti.
